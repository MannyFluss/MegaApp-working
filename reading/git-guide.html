Your papers have a home.

MegaApp runs on GitHub Pages. A separate private GitHub repository holds original PDFs and editable homework workspaces. Your browser autosaves writing and scratch work for offline use.

Connect on your iPad

  1. Create a fine-grained repository key on GitHub. Sign in as MannyFluss. The link suggests a 30-day expiry and Contents read/write.
  2. Under Repository access, choose Only select repositories, then select MegaApp-library. Check that Contents is Read and write. Metadata read access is automatic. No account permissions or workflow access are needed.
  3. Generate the key yourself and copy it. Keep it in your password manager if you want to reconnect later. Do not put it in State, a config file, a repository, or a chat.
  4. Return to Reading, open the document menu and Library connection and settings, paste it into Repository key, and tap Connect library. The app clears the field and holds the key in memory for at most one hour.
The repository link tells the app where the library is. It does not grant access. You need a key on each device; reloading or disconnecting forgets it. Revoking the key in GitHub ends its access everywhere.

Try two devices

  1. Open a PDF, or use the two-page sample. Write on the white pages or surrounding scratch space. Open the document menu and tap Sync workspace.
  2. On another device, open Reading, connect to the same repository, and tap Refresh.
  3. Choose the workspace under In GitHub library. It downloads the original PDF and restores the saved writing, tools and view. Use Sync workspace to pull later edits.

Sync and refresh happen while the app is open. Competing edits preserve both versions and ask which to continue. Cached workspaces work offline once the app shell has prepared; browser storage can still be evicted. Back up an editable workspace together with its original PDF.

What prints

White page boundaries mark the print area. Export marked PDF keeps the original pages, sizes, order and text, adding your ink and highlighting inside those boundaries. Surrounding scratch work is included in Back up workspace, not in the printed PDF. The eraser removes your marks while preserving the original PDF.

A portable location setting

MEGAAPP_ASSET_REPOSITORY=https://github.com/MannyFluss/MegaApp-library

This browser environment variable lives in the State lab and is included in its JSON export. Reading also lets you save it in Repository setting and key setup. Only the location travels in that export. PDF bytes and keys are separate.

What the repository contains

papers/<SHA-256>.pdf
library/<SHA-256>.json
workspaces/<workspace-UUID>.json

A paper's fingerprint gives it a stable path. Uploading identical bytes again verifies the existing original. Its name and size live in a small adjacent metadata record. Editable workspace JSON keeps drawing operations, tools and viewing position. Multiple working copies can share one original; concurrent edits use checked versions without forcing the branch.

This prototype never replaces or deletes an original repository paper. Workspace JSON changes through version-checked commits, preserving conflicting work before resolution. Git history retains old versions. Git suits a modest paper library; frequently changing large audio/video assets need another storage decision.

Limits and trust

  • 25 MiB per PDF, 100 MiB local cache, and up to 1,000 indexed papers in this prototype.
  • The repository must stay private. MegaApp's public deployment repository is not your library.
  • The app does not persist keys. While connected, trusted code running on the same browser origin can access credentials; a masked field is not a sandbox. Untrusted generated apps need separate isolation.
  • A key with Contents write can also change or delete files in the selected repo. The reader only adds/verifies papers, but the key itself grants broader file access within that one repo.
  • Disconnect keeps cached PDFs on this device. Anyone using that browser profile can read them.
